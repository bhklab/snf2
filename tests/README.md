# Understanding The Drug Affinity Tests

The issues with updating IntegrAO for DNF2 had to do with the fact that IntegrAO was built on top of a python package (`snfpy`) developed outside of the lab and that was no longer under development. The original Drug Network Fusion pipeline was built in R using the  package SNFtool (developed in the lab). While SNFpy was modeled after the R package, there were two issues that prevented direct rewriting of DNF in python for the sake of comparison. 

The first issue was that SNFpy did not have functionality for pre-computed affinity matrices. This is required for handling the cell line viability screens where not every drug has a viability entry in each cell line. DNFv1 handled this by computing pairwise correlation distances and then passing that similarity into the SNFtools affinity matrix functionality. 

The second, more minor issue, was that SNFpy had been written using keywords from an outdated version of the scikit-learn python package. These issues have all been remedied in the new iteration SNF2. 

To test and debug our new package, we conducted a few experiments. First we assessed how long it took to compute the affinity matrices from pre-computed matrices. We then made sure that the new pre-computed affinity capability could be used to re-run (not directly recreate) the modality ablation experiments. 


To run these experiments download the required data from ORCESTRA.ca (details can be foundin our [multi-modal embedding repository](https://github.com/digitaltumors/multi-modal-drug-embeddings)). Then simply run

`python3 run <script_name>.py`

where `<script_name>` can be any of `full_test.py`, `basic_test.py`, or `modality_test.py`. Once these have all been run figures can be generated by running `plot_ablations.py`.
